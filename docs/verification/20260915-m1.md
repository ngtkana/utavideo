# 2026-09-15 初期実装（M1）の検証記録

設計の前提にした挙動と、実データに近い素材での性能の記録。

## 環境

- WSL2 上の Ubuntu 24.04
- ffmpeg 6.1.1（Ubuntu パッケージ）、libass 0.17.1（libunibreak・HarfBuzz・FriBidi とリンク）
- Aegisub 3.4.2（Windows）

## libass の自動改行

- `WrapStyle: 0` の .ass を ffmpeg の `subtitles` フィルタで描画した
  - 英単語と空白を含む日本語の行は、PlayRes 1080x1920 で空白の位置で折り返された
  - **空白の無い日本語の長い行は折り返されず、画面の左右にはみ出した**（PlayRes 1920x1080、64px、46文字）
- libass は libunibreak とリンクされているが、既定では VSFilter 互換の改行（空白の位置のみ）になる
- Aegisub 3.4.2 の実行ファイルには `unibreak` という文字列が含まれていなかった。Aegisub の描画でも同じく折り返されないと推測しているが、Aegisub の画面では未確認
- 対応: 長い行は `\N` で改行する運用にし、`check` に行の幅の概算による警告を入れた（`layout.py`）

## 行の幅の計算式

Noto Sans JP、フォントサイズ 64、空白の無い39文字（文字送り幅の合計 39000 / unitsPerEm 1000）を、PlayRes 3840x1080 で描画してインクの幅を測った。

| 条件 | 実測（インク幅） | 予測: winAscent+winDescent 基準 | 予測: unitsPerEm 基準 |
|---|---|---|---|
| Regular、字間 0 | 1707px | 1724px（VF: 1448）/ 1687px（Regular.otf: 1480） | 2496px |
| Bold、字間 2 | 1783px | 1802px（VF） | 2574px |

- libass は `usWinAscent + usWinDescent` の高さをフォントサイズに合わせて拡大している。この基準なら1〜2%の誤差で一致した
- 同じファミリーでもファイルによって winAscent/winDescent が違い、どのファイルが使われるかは実行時まで分からない。概算では、該当するファイルのうち最も広くなる値を使う

## 透過動画の書き出し

- `color=c=black@0` のキャンバスに `subtitles=...:alpha=1` で描画し、`prores_ks -profile:v 4444 -pix_fmt yuva444p10le` で書き出した
  - 1920x1080・4秒の書き出しに約1.7秒
  - ffprobe の表示は `yuva444p12le`
- 単色の背景に重ねて、文字の部分以外が透過していることを確認した

## ブルーバックのキーイング（M2 に向けた試作）

- 1280x720 の青背景の録画を 1920x1080 に lanczos で拡大し、`colorkey=0x0000FF:0.35:0.08,despill=type=blue` で背景画像に重ねた
- 輪郭はおおむねきれいに抜けた。白い服の縁にわずかに紫が残るので、M2 ではパラメータを調整する

## 実データに近い素材での性能

素材: 300秒の wav（44.1kHz・24bit）、背景は 2560x1440・4fps・28フレームの GIF。出力は 1920x1080・30fps。

| 処理 | 時間 | 出力 |
|---|---|---|
| `check`（フォント約1170ファイルの一覧を初めて作る場合を含む） | 4.8秒 | — |
| `check`（はみ出し検査を追加した後。Noto Sans JP の9ファイルを読む） | 9.0秒 | — |
| `preview-bg`（出力先は WSL から見た Windows のドライブ） | 53秒 | 155MB |
| `build`（出力先は Linux のファイルシステム、CRF 18・slow） | 53秒 | 32MB（約 844kbps） |

- Windows のドライブへの書き込みでも、書き出し時間は問題にならなかった
- `init` を実行する前後で、既存ファイルのサイズと更新時刻が変わらないことを確認した
- `build` の出力からフレームを抜き出し、GIF の繰り返し・曲名表示・歌詞・Comment スタイルの表示を目視で確認した
