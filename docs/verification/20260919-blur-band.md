# blur の帯の作り方（測り直し）

2026-09-19 に、ffmpeg 6.1.1（20 スレッド）で測った。
[20260918-shorts.md](20260918-shorts.md) の「帯のぼかし方」の表は、比べた filtergraph を書き残して
いなかった。手元では再現せず（「ぼかし無し」が、同じ graph にぼかしを足したものより遅い順序になって
いる）、同じ graph にフィルタを足して速くなることは無いので、帯の速さの記録はこちらを使う。

## 測り方

1920x1080・30fps・10 秒の動画（`testsrc2` を libx264 で書き出したもの）を背景に、1080x1920 の
`blur` の画面（本編の .ass と縦用 .ass を1行ずつ描く）を組み、`-f null -` で書き出した時間。
3 回の最小。帯の並び以外は同じで、`-stream_loop -1` の背景と音源を入力にしている。

比べた `-filter_complex`（`…` は共通部分）:

```
# 2026-09-18 の実装（vertical.size に合わせてから 1/4 に縮めてぼかす）
[0:v]split[band][frame];
[band]scale=1080:1920:force_original_aspect_ratio=increase:flags=lanczos,crop=1080:1920:(iw-ow)*0.5:(ih-oh)*0.5,setsar=1,fps=30,format=rgb24,scale=270:480:flags=area,gblur=sigma=10,scale=1080:1920:flags=bilinear[bg];
[frame]scale=1920:1080:force_original_aspect_ratio=increase:flags=lanczos,crop=1920:1080:(iw-ow)*0.5:(ih-oh)*0.5,setsar=1,fps=30,format=rgb24,subtitles=filename=main.ass,scale=1080:-2:flags=lanczos[fg];
[bg][fg]overlay=y=(H-h)*0.5:format=rgb,subtitles=filename=vertical.ass,scale=out_color_matrix=bt709:out_range=tv,format=yuv420p[v]

# 今の実装（はじめから 1/4 の大きさに合わせ、fps は split の前で1回）
[0:v]fps=30,split[band][frame];
[band]scale=270:480:force_original_aspect_ratio=increase:flags=area,crop=270:480:(iw-ow)*0.5:(ih-oh)*0.5,setsar=1,format=rgb24,gblur=sigma=10,scale=1080:1920:flags=bilinear[bg];
[frame]…（同じ。fps だけ split の前に移した）…[fg];
[bg][fg]…（同じ）…[v]
```

「ぼかし」の行は、上の `[band]` のぼかしの部分だけを差し替えて測った。

| 帯の並び | 時間 |
|---|---|
| `vertical.size` に合わせるだけ（ぼかし無し） | 3.76 秒 |
| `vertical.size` に合わせて `gblur=sigma=40` | 5.66 秒 |
| `vertical.size` に合わせて 1/4 に縮めて `gblur=sigma=10` → 戻す（2026-09-18 の実装） | 4.68 秒 |
| `vertical.size` に合わせて `boxblur=40:2` | 9.36 秒 |
| **はじめから 1/4 の大きさに合わせて `gblur=sigma=10` → 戻す（今の実装）** | **2.56 秒** |
| 同じ並びで、`fps` を `split` の後（帯と本編に1つずつ）に置く | 2.78 秒 |
| 参考: はじめから 1/4 の大きさに合わせるが、ぼかさない | 2.05 秒 |

- **ぼかし無しがいちばん速い**（同じ graph にフィルタを足して速くはならない）。ぼかし方の比較は
  「ぼかしの中でどれが速いか」として読む
- ぼかしの中では、縮めてから `gblur` を掛ける方法がいちばん速く、`boxblur` がいちばん遅い
  （2026-09-18 の結論と同じ）
- 帯は最後にぼかすので、`vertical.size` いっぱいに lanczos で合わせてから 1/16 の画素数に落とすのは
  無駄になる。はじめから 1/4 の大きさに合わせると 4.68 → 2.56 秒（`preview-bg --vertical` は曲全体を
  この画面で書き出すので、そのまま待ち時間の差になる）
- `fps` を `split` の前に1回だけ置くと、さらに 2.78 → 2.56 秒

## 見え方

1 フレーム目を比べた PSNR（`gblur=sigma=40` を基準）:

| 比べたもの | 帯の部分だけ（上から 600 行） | フレーム全体 |
|---|---|---|
| 2026-09-18 の実装 | 56.1 dB | 58.3 dB |
| 今の実装（はじめから 1/4） | 42.8 dB | 44.0 dB |

- 今の実装は、切り取りと縮小を 1/4 の大きさで行うので、`gblur=sigma=40` との差は少し大きくなる。
  それでも 2026-09-18 に「並べても違いが分からない」と判断した水準（43.1 dB）と同じで、並べて見ても
  区別が付かなかった
- 切り取りの位置が 1/4 の画素単位に丸まるので、`focus` の効きは元の解像度で最大 4px ずれる。
  ぼかした帯なので見えない

## setsar の位置

`setsar=1` は `scale` の**後ろ**に置く。`scale` は表示の縦横比を保つために sar を書き換えるので、
`split` の前にまとめて置いても 1 にはならない。

```
ffmpeg -i bg.mp4 -vf "setsar=1,scale=1080:1920:force_original_aspect_ratio=increase:flags=lanczos,
crop=1080:1920:(iw-ow)*0.5:(ih-oh)*0.5,showinfo" -frames:v 1 -f null -
→ sar:10240/10239 s:1080x1920
```

そのため、`split` の前にまとめられるのは `fps` だけで、`setsar=1` は帯と本編のそれぞれに残す
（画素を触らないフィルタなので、時間には出ない）。

## format=rgb24 の位置

帯の `format=rgb24` は `gblur` の**前**に置いている。後ろに回すと速いが、見え方が背景のファイルの
種類で変わるため、採らなかった。測り方は上と同じ（時間は別の回に測ったので、上の表の 2.56 秒とは
誤差の範囲で違う）。

| 帯の並び | 時間 | 帯の部分だけの PSNR（今の実装を基準） |
|---|---|---|
| `format=rgb24` → `gblur` → 拡大（今の実装） | 2.59 秒 | － |
| `gblur` → 拡大 → `format=rgb24` | 2.29 秒 | 26.4 dB |
| `format=yuv444p` → `gblur` → 拡大 → `format=rgb24` | 2.48 秒 | 50.6 dB |

- 2 行目は、動画の背景（yuv420p）だと `gblur` が色差を半分の解像度で掛けるので、色差のぼかしが
  実質2倍の半径になる。画像の背景（rgb24）では起きないので、**同じ設定でも背景のファイルの種類で
  帯の見え方が変わる**。速さ（−12%）より、見え方がそろうことを採った
- 3 行目（`yuv444p` を挟む）はその問題が無く、速さも −4% だが、画像の背景では RGB↔YUV の変換が
  増える。今の差（0.1 秒）では割に合わないので、そのままにした
