# 2026-09-17 サムネイルの書き出し

サムネイル（issue #20）の設計の前提にした、Aegisub と ffmpeg の挙動の記録。

## 環境

- Aegisub 3.4.2（Windows）、映像の読み込みは FFmpegSource（既定）
- ffmpeg 6.1.1（Ubuntu 24.04 のパッケージ、libass 付き）。WSL2 で実行
- 入力はすべて `lavfi` で作った合成の素材（下の各節に書く）

## Aegisub で PNG を下敷きに開けるか

1920x1080 の PNG（100px ごとの格子、中央に赤い十字、外周に青い枠）を、`[Aegisub Project Garbage]` の `Video File:` に指定した .ass（PlayRes 1920x1080）で開いた。

| 確かめたこと | 結果 |
|---|---|
| PNG を映像として読み込めるか | 読み込めた（1フレームの映像になり、位置は `0:00:00.000 - 0`） |
| 解像度の食い違いの確認が出るか | 出なかった（PNG と PlayRes が同じ） |
| `0:00:00.00`〜`9:59:59.99` の行が描かれるか | 描かれた |
| `\pos` の座標が PNG の画素と合うか | 合った（`\pos(960,540)` が十字の中心、`\an7\pos(100,100)` が格子の (100,100)） |

- ファイルのドラッグなど、拡張子で映像かどうかを決める経路では、`.png` が映像として扱われない可能性がある。確かめたのは `Video File:` の経路（メニューの「ビデオを開く」と同じ）
- `Video File:` に**相対パス**（`../build/thumbnail/bg/main.png`）を書いて効くかは確かめていない
- JPEG は確かめていない（下敷きは PNG だけ書く）

## 入力側のシークとフレームの時刻

4 秒・10fps の mp4（フレーム N の輝度が `16+5N`、可逆で符号化）と、4 秒・4fps の GIF（輝度 `16+12N`）で、`-ss <秒> -i <入力> -frames:v 1` の1フレーム目を調べた。

| 入力 | `-ss` | 出てきたフレーム |
|---|---|---|
| mp4 | 0 | 0（0.0 秒） |
| mp4 | 1 | 10（1.0 秒） |
| mp4 | 2.5 | 25（2.5 秒） |
| mp4 | 3.85 | 39（3.9 秒） |
| mp4 | 3.95・3.99・4.5 | なし（終了コード 0、出力ファイルが作られない） |
| GIF | 2.5 | 10（2.5 秒） |
| GIF | 3.7 | 15（3.75 秒） |
| GIF | 3.8・3.99・4.5 | なし（終了コード 0、出力ファイルが作られない） |
| PNG（画像） | 1 | なし（終了コード 0、出力ファイルが作られない） |

- 出てくるのは、`-ss` の時刻**以降の最初の**フレーム。最後のフレームの時刻より後を指すと、長さ（ffprobe の `format=duration`。mp4・GIF とも 4.000000）より前でも何も書かない
- 画像に `-ss` を付けると、0 より後の時刻では何も書かない。utavideo は画像に `-ss` を付けず、`at` を書いたらエラーにする
- 何も書かなかったときは `.partial` が作られないので、utavideo は ffmpeg の正常終了の後に出力の有無を確かめてエラーにする
- ffprobe の長さは、mp4 と GIF では取れ、PNG では `N/A`
- `-ss 2.5` を付けた mp4・GIF と、付けない mp4 のどれでも、最初のフレームの `pts_time`（`showinfo`）は 0

## シークした後の .ass の時刻

黒い背景に、画面全体を塗る図形（`\p1`）の行を1つだけ置き、`format=rgb24,subtitles=` で描いて最大の輝度を見た。

| 背景 | 行 | 描かれたか |
|---|---|---|
| mp4、`-ss 2.5` | `0:00:00.00`〜`0:00:00.02` | 描かれた |
| GIF、`-ss 2.5` | `0:00:00.00`〜`0:00:00.02` | 描かれた |
| mp4、`-ss 2.5` | `0:00:01.00`〜`9:59:59.99` | 描かれなかった |
| PNG | `0:00:00.00`〜`9:59:59.99` | 描かれた |

入力側でシークしても、描かれるのは .ass の 0 秒の状態。

## フェードのタグと 0 秒の状態

PNG の背景に、`0:00:00.00`〜`9:59:59.99` の行で描いた（輝度 255 は不透明、0 は透明）。

| タグ | 輝度 |
|---|---|
| `\fad(150,0)`・`\fad(1,0)`・`\fade(150,0)` | 0 |
| `\fad(0,150)`・`\fad(0,1)`・`\fad(0,0)` | 255 |
| `\fade(255,0,0,0,150,1000,2000)` | 0 |
| `\fade(255,0,0,200,300,1000,2000)` | 0 |
| `\fade(255,0,0,-100,-50,1000,2000)` | 255 |
| `\fade(0,255,0,0,150,1000,2000)` | 255 |
| `\fade(0,0,255,0,0,1000,2000)` | 255 |

- 2つの引数の形はフェードインが 0 より長いと透明になる。7つの引数の形は、0 秒の不透明度が `a1`〜`a2` の途中（`t2 > 0`）になる
- utavideo は、`\fad` のインが 0 より大きい行と、`\fade` の `t2 > 0` かつ `a1 ≠ a2` の行を警告する
- `lyrics.fade_ms` の自動フェード（`\fad(150,150)`）を付けると 0 秒で文字が消えるので、サムネイルには付けない

## .ass に文字をそのまま書くときのエスケープ（libass）

DejaVu Sans Mono 40px で1行を描き、文字のある列の範囲と、描いた画素の一致で比べた。

| 行の文字 | 描かれたもの |
|---|---|
| `a{b` | `a{b`（閉じない `{` は文字として描く） |
| `a{b}c` | `ac`（`{…}` はタグ） |
| `a\{b`・`a\}b` | `a{b`・`a}b` と同じ画素 |
| `x\{a\}` | `x{a}` |
| `a\b`・`a\Ab` | `\` をそのまま描く |
| `a\\b` | `a\\b`（`\\` はエスケープではない） |
| `a\\{b` | `a\{b` |
| `a\Nb` | 改行 |
| `a\{}N` | `a{}N`（`\{` が先にエスケープとして読まれる） |
| `a` + U+2060 + `b` | `ab` と同じ画素 |
| `a\` + U+2060 + `Nb` | `a\Nb` の4文字 |

- `{`・`}` は `\{`・`\}` と書けば文字として描かれる
- `\N`・`\n`・`\h` を文字として描くエスケープは無い。`\` の後に幅の無い WORD JOINER（U+2060）を挟むと、`\N` として読まれず、見た目も変わらない
- Aegisub に同梱の libass と、Aegisub の編集欄での見え方は確かめていない

## PNG の圧縮

1920x1080 の画像を `-c:v png -pix_fmt rgb24` で書き直した（バイト数）。

| 画像 | 既定 | `-compression_level 9` | `-compression_level 100` | `9` と `-pred mixed` |
|---|---|---|---|---|
| `testsrc2` | 231,867 | 218,839 | 218,839 | 205,077 |
| `gradients` にノイズ | 2,163,277 | 1,998,845 | 1,998,845 | 1,999,778 |
| `mandelbrot` | 977,546 | 965,862 | 965,862 | 798,299 |

- `-compression_level 9` で 1〜8% 小さくなる。`100` は `9` と同じ
- `-pred mixed` は画像によって効き方が大きく違う（合成した画像なので、写真やイラストでの差は未確認）。utavideo は `-compression_level 9` だけを付ける
- 1枚だけ書くときは `-frames:v 1 -update 1` を付ける。`main.partial.png` のように連番を含まない名前でも書ける

## 背景の合わせ方（`crop`・`pad` の位置の式）

横 403px の横グラデーション（x 列の輝度 `x*255/402`）を 100x100 に `cover` で合わせ、左端の列の輝度を見た。

| 式 | 左端の輝度 | 残った範囲 |
|---|---|---|
| `crop=100:100:(iw-ow)*0:(ih-oh)*0.5` | 0 | 左端 |
| `crop=100:100:(iw-ow)*0.25:(ih-oh)*0.5` | 48 | 左から 1/4 |
| `crop=100:100:(iw-ow)*0.5:(ih-oh)*0.5` | 96 | 中央（`crop=100:100` と同じ） |
| `crop=100:100:(iw-ow)*1:(ih-oh)*0.5` | 192 | 右端 |

100x403 の白い画像を 403x100 に `contain` で合わせた（背景は 25px 幅になる）。

| 式 | 白い列 |
|---|---|
| `pad=403:100:(ow-iw)*0:(oh-ih)*0.5` | 0〜24（左に寄る） |
| `pad=403:100:(ow-iw)*0.5:(oh-ih)*0.5` | 189〜213（中央） |
| `pad=403:100:(ow-iw)*1:(oh-ih)*0.5` | 378〜402（右に寄る） |

- `focus = [0.5, 0.5]` の式は、今までの `crop=W:H`（位置の既定は中央）・`pad=W:H:(ow-iw)/2:(oh-ih)/2` と、rgb24・yuv420p のどちらの入力でも同じ画素になった（`-f md5` が一致）
