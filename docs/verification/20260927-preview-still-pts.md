# 2026-09-27 preview --at の静止画と .ass の時刻合わせ

`preview --at`（`--duration` 無指定）の静止画に、その時刻の歌詞が描かれない不具合（issue #137）の原因調査と、直したときの前提にした実測。

## 環境

- ffmpeg 9.0.2（Homebrew、libass 0.17.5 付き）。macOS で実行
- 入力は `lavfi` で作った 640x360・4fps・0.5秒の GIF（2フレーム、`testsrc`）

## 起きていたこと

`preview._render_still` は、合成した .ass（曲全体の絶対時刻）をそのまま `subtitles` フィルタに渡し、背景だけを `-ss <at>` でシークしていた。`docs/verification/20260917-thumbnail.md` の「入力側でシークしても、最初のフレームの時刻は 0 になる」という前提のまま設計されていたため、.ass の 0 秒の状態（＝曲の先頭）が描かれていた。

## 直し方の検討: .ass を巻き戻す案は不採用

.ass 側を `-at` 秒ぶん巻き戻す案（`pysubs2.SSAFile.shift`）を最初に試したが、`\fad`・`\move` などの相対時刻タグが行の**元の開始時刻**からの相対値であるため、巻き戻すと「行の途中から始まる」はずの状態が「行の先頭（フェードインの真っ最中）」に化けてしまう。たとえば `\fad(150,150)` の効いた行を、本来の開始から 1.2 秒後の状態として描きたい場合、巻き戻すと開始 0 秒＝フェードインの不透明度 0 の状態になり、何も描かれない（`docs/verification/20260918-shorts.md` に既にある「区間の頭をまたぐ行の \\move・\\fad がずれる」と同じ問題）。

採用したのは逆の方向: .ass は元の絶対時刻のまま渡し、代わりに **背景フレームの pts を `at` に合わせて進める**（`setpts`）方式。こうすると `\fad`・`\move` は行の元の絶対時刻を基準に正しく評価される。

## `-ss` 後のフレームの pts は 0 とは限らない（新しい実測）

`20260917-thumbnail.md` の実測は 4 秒の mp4・GIF の 1 本だけで、`-ss` の値を 0〜3.85 の範囲で振っていた。今回、0.5 秒（2フレーム）の短い GIF で同じことを確かめたところ、前回とは違う結果になった。

`-ss <値> -i loop.gif -frames:v 1 -vf showinfo` で出た `pts_time`:

| `-ss` | 出てきた `pts_time` |
|---|---|
| 0.00 | 0 |
| 0.05 | 0.20 |
| 0.10 | 0.15 |
| 0.15 | 0.10 |
| 0.20 | 0.05 |
| 0.24 | 0.01 |
| 0.25 | 0 |
| 0.30 以降 | 何も書かない（終了コード 0） |

- `-ss` の値が `(0, 0.25)` の範囲では、`pts_time` は `0.25 - (-ss の値)` になり、**0 にならない**（`-stream_loop -1` を付けても付けなくても同じ）
- 素材の長さ・フレーム構成（このケースは 0.25 秒間隔で 2 フレームしか無い）によって挙動が変わる可能性があるため、「シーク後は必ず 0 になる」とは前提できない

この pts のまま `setpts=PTS+{at}/TB` で単純に `at` を足すと、素材の位置によって足し込む前の基準がずれ、`at` と無関係な場所で歌詞の表示・非表示が変わってしまう（`--at`違いで背景ループの位相だけを揃えた 2 枚が、歌詞側の巻き込みで一致しなくなった。実際にテストで検出: `test_preview_still_wraps_at_for_a_looping_background`）。

## 直した式

`setpts=PTS-STARTPTS+{at}/TB` で、まずその場で出てきた最初のフレームを 0 に正規化してから `at` を足す。`PTS-STARTPTS` は基準がどこであっても 0 にするので、上の実測のようなシーク後の pts のずれ方に依存しない。

同じ GIF・同じ .ass（区間外なので歌詞は描かれないはず）で、`--at` の位相だけ揃えた2つの静止画（背景ループの中身は同じはず）を比べ、`setpts=PTS+{at}/TB` では画素が一致しない（歌詞が片方だけ薄く描かれる）ことと、`setpts=PTS-STARTPTS+{at}/TB` では一致することを確認した。
